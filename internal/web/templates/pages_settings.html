Pages is off on this server

Sites are served from their own address, never from Atelier's, so a site's pages can't reach your session. To turn Pages on:

  1. Add a DNS name for sites that points at the same server, for example a DNS rewrite pages.example.lan → <server IP> in AdGuard Home or Pi-hole.
  2. Add a proxy host for that name in Nginx Proxy Manager that forwards to the same Atelier container and port as the app.
  3. Set ATELIER_PAGES_URL=http://pages.example.lan (or https:// with a certificate) on the Atelier container and restart it.

Sites then live at <pages>/{{$v.Repo.Owner}}/{{$v.Repo.Name}}/, and a repository named {{$d.UserSite}} is served at <pages>/{{$v.Repo.Owner}}/. See docs/pages.md.

{{else if $d.Private}}

Private repositories can't publish on the Pages address

Every site shares the Pages address, so a sign-in there would let any published site's script read a private site with your credentials. Make this repository public in Settings, or give the site a verified custom domain: that's its own origin, and only people who can read the repository get in.{{if $d.Site.Enabled}} Its site is offline until then.{{end}}
